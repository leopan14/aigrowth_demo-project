### 统一 4 层员工模型（对应 §3.5 Agent 生命周期）

| 层级 | English Title | 中文岗位 | 职责映射 | 对应原文生命周期 |
|---|---|---|---|---|
| **L1** | Director / Head | 总监 / 团队 Lead | 决策、对外签字、申报升级 | Perceive + Escalate |
| **L2** | Senior Expert | 资深专家 | 复杂场景判断、调取经验库 | Plan (复杂分支) + Reflect |
| **L3** | Specialist | 执行专员 | 标准任务批量执行 | Act |
| **L4** | QA Reviewer | 质量审核员 | 上线前自检、Critic 闸门 | Critic |

工程映射：每位员工 = 一条独立 LLM 调用链 + 专属 prompt + 专属工具集；同一 Agent 内部 4 员工串行流水，由 Director 总签字。

## Slide 10 · 行为规范 · 退役机制 · 申诉路径

### 10.1 Code of Conduct（员工手册）

🚫 全员红线（任何员工不可触碰）

| 红线 | 触发后果 | 出处 |
|---|---|---|
| 跨过 Compliance 直接触达 | Kill Switch 立即熔断 | §5.10 |
| 跨过 Resolver 直接执行 | 任务作废 + 决策追溯 | §5.9 |
| 未经 Critic 上线 AI 生成内容 | 24h 回滚 + 重审 | §3.5 |
| 学习"定位 / 合规 / 品牌底线" | 权重提案被 Reviewer 拒绝 | §6.2.2 |
| 压缩探索流量 < 10% | Reflection 拒绝权重更新 | §6.2.1 |

### 10.2 申诉与升级路径（Escalation Ladder）

```
   员工自检失败 → QA Reviewer 复审 → 同部门 Director 裁决 →
   ↓ (Director 仍无法决策)
   Resolver 跨部门裁决 → Compliance 合规裁决 →
   ↓ (跨 Agent 死锁 / 红线触发)
   Planner 项目级决策 →
   ↓ (项目级失败)
   ⚠️ 升级到人类（客户成功 / 合规负责人 / 行业研究负责人）
```

### 10.3 退役机制（Termination Protocol）

| 退役类型 | 触发条件 | 处理方式 | 原文 |
|---|---|---|---|
| Persona 退役 | 与真实反应严重偏差 | 自动退役并替换 | §5.12.4 / §6.1.2 |
| 模板退役 | 灰度期表现低于阈值 | 回滚到上一版本 | §5.12.4 |
| Agent 临时停职 | Kill Switch 触发 | 单 Agent 熔断 + 人审 | §2.2 L6 / §6.5 |
| 项目级解散 | 重大合规事故 / 客户终止 | 全员暂停 + 审计 + 24h 回滚 | §6.5 |
| 数据回滚 | 客户按回滚键 | 切回上一 weight_version | §5.11.6 |
